# Cost - Agent Configuration

## Root Configuration

Inherits all behavior from `/AGENTS.md` at the monorepo root. Local rules extend or override the root file for this repository.

## Project Context

This repository is the AI application cost evaluation site at [cost.hagicode.com](https://cost.hagicode.com), built as a static Astro site with one SSR-capable React island and generated i18n resources.

## Working Directory

Run commands from `repos/cost/`.

## Key Commands

```bash
pnpm install
pnpm run dev
pnpm run typecheck
pnpm run lint
pnpm test
pnpm run i18n:check
pnpm run i18n:generate
pnpm run build
pnpm run preview
```

`pnpm run dev` serves on port 36291. `dev`, `test` and `build` run `prepare:i18n` (`i18n:generate`) first.

## Agent Guidelines

- Astro 7 and Vite 8 require Node.js 22.12 or later; this repository standardizes on Node.js 24 or later.
- Astro owns routes, document structure, build-time metadata, and static output. Keep browser interactions in the React island.
- Keep the React island's initial render deterministic: default locale, light theme, and default form values. Apply URL, stored, browser language, theme, and region preferences after hydration.
- Keep locale-sensitive content together when extracting a section would break client-side language switching or duplicate copy.
- Route all user-facing copy through the `hagi18n` i18n flow.
- Edit translations only in `src/i18n/locales/<locale>/translation.yml` (base `en-US`, nine target locales; see `hagi18n.yaml`).
- Use `pnpm run i18n:check` to validate locale consistency before committing.
- `robots.txt`, `sitemap-index.xml`, `rss*.xml`, and the favicon are generated by `@hagicode/hagilight` (`astro.config.mjs`); do not hand-write same-named files in `public/`.
- `pnpm run build` runs `typecheck`, `astro build`, then `check-built-site.mjs`.
- Treat this as a static site; do not add an application server. Keep `VITE_BASE_PATH`, `VITE_SITE_URL`, `VITE_APP_VERSION`, and `dist/` compatible with publication.

## PostHog Events

Three site-level events go through `captureSiteEvent` in `src/lib/posthog-events.ts`. The table in that file is the source of truth; keep this section in sync with it. The wrapper sends nothing when `window.posthog` is missing, when the visitor has opted out, or when sending throws.

| Event | Sent when | Properties |
|-------|-----------|------------|
| `assessment_completed` | The first produced result shown after the visitor changes an input in this page session (`AssessmentLanding`). At most once per page session, tracked in memory only. Not on initial render, re-render, later result changes or a returning mount. | `currency`: `CNY` or `USD`. `income_preset`: `starter`, `growth`, `senior`, `staff`, `principal` or `custom`. `verdict_tone`: `safe`, `warning` or `danger`. |
| `assessment_shared` | The clipboard write of a share succeeds (`use-share-current-site`). A failed share sends nothing. | `has_result`: boolean, true when a result existed when the share ran. |
| `boost_cta_clicked` | The share button in the Hagicode boost section (`HagicodeBoostSection`) is activated, before the copy. | None. |

Income preset keys map to the preset rows in `form-options.ts`: CNY 13, 26, 40, 60 and 100 (万) and USD 18, 36, 55, 83 and 138 (k) map in that order to `starter`, `growth`, `senior`, `staff` and `principal`. Any typed amount is `custom`. No income amount, URL, free text or token count is ever sent.

Deduplication: a business event is the canonical record of its action. If a control also reports `cta_click`, dashboards must not add the business event to `cta_click` counts. The boost share button can send `boost_cta_clicked` and, on a successful copy, `assessment_shared`; these are two distinct actions and both are counted.

## Package management

- The repository uses pnpm, pinned in `package.json` `packageManager`. Run `corepack enable` once, then `pnpm install`. `pnpm-lock.yaml` is the only lockfile; do not commit `package-lock.json`.
- Settings live in `pnpm-workspace.yaml`. `allowBuilds` lists the dependencies whose install scripts may run (reviewed individually, `false` means reviewed and denied); review any new dependency that has an install script and add it there.
- A local registry mirror belongs in `~/.npmrc` only. Never commit a `registry=` line or a mirror URL; `pnpm run check:registry` (also run in CI) fails on any non-`registry.npmjs.org` `tarball` in the lockfile and on mirror hosts in tracked files.
- Undeclared imports fail under pnpm's strict layout: declare the package instead of hoisting it.
